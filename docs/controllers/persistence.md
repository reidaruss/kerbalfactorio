## 1. Mission
Save and restore arbitrarily large worlds cheaply and reliably: regenerate the natural universe from a seed, store only player modifications as diffs, stream chunks on demand, and keep saves forward-compatible as the game evolves.

## 2. Scope & owned subsystems
- **Seed+diff model** — the universe regenerates from a seed; only player changes are stored.
- **Chunked region storage** — world partitioned into streamable, independently loadable/savable chunks.
- **Serialization format** — compact (custom binary) for factory state at scale; structured for player/meta data.
- **World database / save container** — single-player file(s) and server-side store.
- **Streaming** — load/unload chunks tied to core-engine active bands & networking AOI.
- **Versioning & migration** — schema evolution without bricking saves.
- **Non-goals:** generating the world (→ world-gen; we store its *diffs* and seed); deciding what state matters (each domain declares its persistable state).

## 4. Architecture & approach
- **Seed+diff:** store the world seed + a sparse set of diffs keyed by chunk: terrain edits (voxel patches), deposit depletion, placed/removed factory entities + their state, looted-POI flags, player inventory/progress. On load, regenerate from seed, then apply diffs.
- **Chunking:** the world is partitioned (per body, per region) into chunks that load when entering core-engine's active band / networking AOI and flush when leaving. On-rails factory chunks persist as their rate model + buffers, not per-entity (factory-sim FS-4).
- **Formats:** factory/world chunks → compact binary (versioned headers); player progress, tech, quests, settings → structured (binary or readable) for easier migration. Each domain provides serialize/deserialize for its own state; persistence owns the container, indexing, streaming, and versioning.
- **MP:** server holds the canonical store; clients regenerate from seed and receive diffs via networking (clients don't need the whole save).

## 5. Interfaces & dependencies
**Depends on (inbound):**
- world-gen: the seed + the diff set (terrain edits, depletion, POI flags).
- factory-sim: factory state snapshot (entities, buffers, on-rails rate models).
- gameplay: player progress (tech, quests, inventory, looted flags).
- physics: vessel orbital state (element sets) + active-vessel state.
- core-engine: chunk↔active-band mapping, `UniverseCoord` keys; networking: AOI streaming triggers, server-store role.
**Provides to (outbound) — published contracts (Phase-1 designed — [persistence-phase1.md](../phase1/persistence-phase1.md) §2,§5,§6):**
- **`IPersistable`** — the per-domain serialize/deserialize contract (`DomainId`, `SchemaVersion`, `SaveDiffs(FChunkKey, FSaveWriter&)`, `LoadDiffs(FChunkKey, FSaveReader&, savedVersion)`, `EnumerateDirtyChunks`). Each domain implements it over its OWN pinned state; persistence never interprets the bytes.
- **`FChunkKey`** + `truncate(FQuadKey → region)` mapping rule (PS-5).
- **Save/load orchestration + atomic single-slot container** (`Save(slot)`/`Load(slot)`, PS-6); `FSaveWriter`/`FSaveReader` byte cursors handed to each domain.
- **Versioned header (PS-4)** + the two payload formats (`.ofc` compact binary / `.ofd` structured TLV, PS-3).
- **`DiscoveryScope` (PS-46/PS-47, web)**: `reseatDiscovery(core, bodyId, disc)`, `noteDiscoveryBody(bodyId)`, `discoveryBytesFor(core, bodyId)`, `discoveryScopeReport()`. **The contract other domains have to honour: any body change must call `reseatDiscovery` from inside the body scope**, which `Boot.ts` does through its `discReseat` holder; anything that re-cuts `/core`'s field by another route must call `noteDiscoveryBody` or the stash will be keyed to the wrong body. Consumes `/core`'s already-exported `of_disc_reset` / `of_disc_serialize` / `of_disc_alloc_bytes` / `of_disc_deserialize`. **No ABI change.**
- **`SaveWorld` + `WORLD_KEYS` (PS-40, web)** — the body dimension of the live slot. `body` on the record, `others` beside it, one slot per mode still. **The contract other domains have to honour: a new `SaveSlot` field must be classified body-scoped or global, and the compiler enforces that it is classified.** BodyId is /core's `BodyParams::bodyId` (0 Forge, 1 Cinder), which is PS-5's `FChunkKey` first component finally reaching the web save.

**`IPersistable` per-domain state each must serialize (Wave-2 asks — routed by Admin):**
- **core-engine** (`CoreEngine`, GLOBAL): `worldSeed` + observer `FUniverseCoord`/`FFrameId` + `SimTime`/`TickIndex` + floating-origin anchor. Also owes a **save-quiesce tick boundary** (capture all domains at one `TickIndex`).
- **world-gen** (`WorldGen`, CHUNK): **deposit depletion only** — `(depositId, remaining)[]` per region. Terrain NOT saved (regenerates — PS-7).
- **physics** (`Physics`, GLOBAL): craft `FOrbitalElements + Mode + DominantFrame` (~10 doubles) (+`r,v` if active on surface).
- **factory-sim** (`FactorySim`, CHUNK): full per-entity SoA + `TransportLine` contents (active chunk) **or** `FRailState` (on-rails chunk, PS-8); align chunk granule to `FChunkKey.RegionDepth`.
- **gameplay** (`Gameplay`, GLOBAL): inventory + avatar position/body/frame/control-mode + objective progress flags.

### 5.1 THE BUCKET BOUNDARY (PS-40) — READ THIS BEFORE ADDING A FIELD TO `SaveSlot`

The compiler will stop you adding a field without classifying it. It cannot tell you the classification is **right**, so this is the part that has to be written down.

| BODY-SCOPED (`WORLD_KEYS`, 12) | why |
|---|---|
| `voxels` | absolute body-frame metres |
| `depletion` | index into a node array `NodeField.populate` refills per body |
| `patches` | index into the per-body ore field. **Both bodies have 4.** |
| `rocks`, `trees` | `[latCell, lonCell, slot, remaining]` on a lattice whose step and whose longitude wrap count are both derived from `bodyRadiusM` |
| `buildings`, `machines`, `sites`, `structures`, `pads` | body-frame positions and a metric site grid anchored to this body's surface |
| `discovery` | one `g_disc` whose resolution is a function of radius; `deserialize` ADOPTS the stream's radius. **PS-46/PS-47: the LIVE field is now body-scoped too, via `world/DiscoveryScope.ts`, and the bytes a slot carries are the NAMED body's** |
| `health` | `[healthKey, hp]` for **placed things**, which stand on a body |

| GLOBAL (`GlobalKey`, 15) | why |
|---|---|
| `version`, `seed`, `savedAt`, `mode`, `body`, `others` | the slot's own identity. **`seed` mints every body** (`PlanetBody.create(core, bodyId, seedLo, seedHi)`) and must not become per-body |
| `pack` | `g_inv`, one module singleton with no position in it |
| `progress`, `hotbar`, `assisted`, `vitals` | the player and the run, not a place |
| `dayT`, `stationPower` | one sun for the system; a station is not on a body at all |
| `vessels`, `player` | see the trap below |

**THE SIX PLACES THE NEXT PERSON WILL GET IT WRONG.**

1. **`player` is in the wrong bucket ON PURPOSE, and the gate will never say so.** A player anchor is bare lat/lon/alt with no body in it, so a Forge anchor still restores at the same lat/lon on a 200 km moon. It is classified global because `SavePlayerAnchor` is PH-68's record and this domain will not edit it (R-BODY-1). **The classification list therefore contains one entry that is knowingly wrong**, which is the honest limit of a gate that proves a decision was made rather than that it was correct. `vessels` beside it is genuinely global: a rocket in orbit about Forge is not "on" Cinder.
2. **`discovery` reads as player state and is body state.** It sits between `pack` and `sites` in the interface and its comment says "what the player has SEEN". It is the field that already destroyed data. **AND IT HAD A SECOND HALF NOTHING ON THIS LIST COULD CATCH (PS-46):** classifying the SAVE FIELD correctly does nothing about the LIVE field, which is one `g_disc` in `/core` with no body in it. A `WORLD_KEYS` entry is a statement about bytes on disk; if the thing producing those bytes is a process-wide singleton, the bucket is right and the world is still wrong. The gate cannot see that and never will: when adding a body-scoped field, ask separately **where does the live state live, and who re-cuts it when the body changes.**
3. **`health` and `vitals` are adjacent, similarly named, and in opposite buckets.** `health` is what is broken in the base; `vitals` is the player's own hit points.
4. **Never build a `SaveWorld` by hand.** `viewForBody` assigns every key in `WORLD_KEYS`, including the absent ones as an explicit `undefined`, because **a spread of an object that lacks a key leaves the previous value standing and the previous value is another planet's.** Go through `worldOf` or `emptyWorld`; `emptyWorld` is typed `SaveWorld` so the compiler catches a new REQUIRED field, and it omits the optional ones deliberately so "absent" keeps its one documented meaning.
5. **The top-level world is whichever body wrote LAST.** Never assert `slot.body === 0` and never read `others[0]` positionally. The first draft of `twobody.mjs` did both and went red on a correct build.
6. **The carry-through is cleared at the TOP of `loadSlot`**, not on each early return, so an exit added later cannot leak a refused slot's other bodies into the next autosave. A slot holding a body id nothing recognises is **carried, not dropped**: throwing away a world you cannot identify is the destructive option.

Line caps: `Persist.ts` was kept under 400 by splitting `PersistSlot.ts` out. `SaveGame.ts` (480) and `Gameplay.ts` (554) are over, and both were over before this work.

**Load order contract (§4.5):** CoreEngine → WorldGen (regen+depletion) → Physics → FactorySim → Gameplay (player placed last into the completed world).

**Open negotiations (flagged to Admin as DEPENDENCIES):** (1) final `RegionDepth` — joint pick with factory-sim + core-engine so 1 save region ≈ 1 factory chunk proxy; (2) the save-quiesce tick handle from core-engine.

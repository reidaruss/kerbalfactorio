## 1. Mission
Own the foundational layer every other domain stands on: the 64-bit coordinate system, floating origin, reference-frame hierarchy, the **active/on-rails** simulation framework, the tick/time model (including time-warp), and the data-oriented ECS foundation. If this layer is wrong, everything above it is wrong.

## 2. Scope & owned subsystems
- **Universe coordinate system** — 64-bit (double or int64 fixed-point) authoritative positions.
- **Reference-frame hierarchy** — star → planet → vessel; frame switching at SOI boundaries (coordinates with [physics](physics.md)).
- **Floating origin** — rebasing the world around the active observer so GPU/physics see near-origin floats.
- **Active/on-rails framework** — the generalized [MASTER_PLAN §3](../MASTER_PLAN.md#3-the-unifying-principle-active-vs-on-rails) mechanism: registration, promotion/demotion of entities between simulated and abstracted states.
- **Tick & time** — fixed-step sim tick (decoupled from render FPS), time-warp orchestration, sim/render interpolation.
- **ECS foundation** — entity/component layout conventions, system scheduling, the boundary between engine Actors and the data-oriented sim.
- **Floating origin, BY FILE (added explicitly 2026-08-03, CE-21).** `web/src/world/FloatingOrigin.ts` and the `OriginRebased` contract around it. This was always inside "floating origin" in §1, and the file nevertheless carried **zero decision tags and appeared in no controller document for a year**, which is how the *lifecycle* around it (who unsubscribes, what the origin means when the body changes) came to be owned by nobody. Naming the subsystem is not the same as naming the file, and a load-bearing file that no document claims is a defect in the agent architecture before it is a defect in the code. **Any future subsystem this domain owns gets its files listed here, not just its concept.**
- **The world/session lifecycle, BY FILE (added 2026-08-03, CE-20).** `web/src/world/WorldSession.ts`, `web/src/app/Lifetime.ts`, `web/src/sim/wasm/HandleLedger.ts`, `web/src/app/DebugLifecycle.ts`, and the **`Services` record's own lifetime** (`web/src/app/Services.ts`: what is fixed at boot, what follows the session, and who may tear anything down). The teardown *contract* is this domain's even where the object being torn down is another domain's.
- **Non-goals:** rendering (→ rendering), the physics math itself (→ physics), factory rules (→ factory-sim). This domain provides the *substrate* they run on. Note the boundary this pass had to hold: core-engine owns *what dispose means and who calls it*; a domain still owns *what its own dispose does*.

## 4. Architecture & approach
- **Floating origin:** maintain a `UniverseOrigin` (64-bit) per active observer. When the observer drifts beyond a threshold (e.g. 4 km), rebase: subtract the delta from all rendered/physics transforms, add it to `UniverseOrigin`. Physics & GPU never see large coords.
- **Reference frames:** each celestial body defines a frame (position + rotation in the universe). The active observer is parented to the dominant frame (its current SOI). Frame switches (SOI crossings) are events emitted to [physics](physics.md) and [rendering](rendering.md).
- **Active/on-rails registry:** every simulatable thing registers with a `SimProxy` exposing two modes — `Active` (full sim, owned by the relevant domain) and `OnRails` (analytic state: an orbit element set for vessels; a production-rate model for factories). Core-engine owns *promotion/demotion* triggers (distance, load state, time-warp); domains own the *content* of each mode.
- **Time-warp:** in on-rails mode, advance analytic state by Δt directly (no per-tick sim). Active entities cannot be warped past physics stability limits → warp is gated by what's currently active. (MP interaction is Admin Q1.)
- **ECS boundary:** gameplay-significant but low-count things (player, active vessel) may be engine Actors; high-count things (factory entities, debris, items) live in the data-oriented sim. Define the bridge once, here.

## 5. Interfaces & dependencies
**Depends on (inbound):** the engine (D-001). Nothing else — this is the base layer.
**Provides to (outbound) — published contracts:** *(now pinned with concrete signatures in [Spike 1 §5](../spikes/spike1-core-engine.md#5-pinned-api-contracts-rendering--world-gen-code-against-these); deltas flagged below — additive, no breaking change vs. prior prose)*
- `UniverseCoord` (64-bit position) + `ToEngine/FromEngine`. **Now carries its `FFrameId`** — a coord is meaningless without its frame; `ToEngine/FromEngine` take an explicit `FFloatingOrigin`. **Used by: all.**
- `ReferenceFrame` / `IFrameGraph` + `FSOIChangeEvent`. **SOI event now carries position AND velocity re-expressed in the new frame** (physics needs both at a crossing). **Used by: physics, rendering, world-gen.**
- `SimProxy` (`ISimProxy`/`ISimRegistry`) + Active/OnRails promotion/demotion hooks. Core-engine owns promotion/demotion + hysteresis; domains own each mode's *content* (`EvalOnRails/StepActive/OnPromote/OnDemote`). **Used by: physics, factory-sim, networking.** **RC-10/CE-7 delta (additive, non-breaking):** `ISimProxy` now carries a **defaulted `PromotionRadius()`** (bounding-sphere radius about `Position()`, default `0`) so the bubble test treats **mixed granularity** uniformly — a point vessel (radius 0, unchanged) and a coarse factory chunk (radius = chunk half-extent) share one extent-aware `gap()` test. **Affects: factory-sim** (overrides `PromotionRadius()` to return chunk half-extent); **physics** unaffected (inherits 0, no code change). Spike 1 §3.2.1, §5.3.
- `SimClock` (`ISimClock`): fixed tick, warp, interpolation `Alpha`, **+ `TickIndex()`** (determinism/replication, D-004), **+ `QuiesceAtTickBoundary(body)`** (CE-8 / Phase-1 C-7: save-quiesce fence — parks advance at end-of-tick N, runs `body(N)` with no domain advancing, resumes; guarantees a no-torn-read cross-domain snapshot at one `TickIndex`). **Used by: all sim domains; `QuiesceAtTickBoundary` used by persistence.** Both additions additive, non-breaking (Spike 1 §5.4/§5.4.1).
- Events: `OnOriginRebased(DeltaEngine, NewOrigin)` and `OnSOIChange(FSOIChangeEvent)` — the rebase/frame-switch hook points for rendering, world-gen, audio.
- **`IPersistable` (CoreEngine, GLOBAL) impl + `FChunkKey.RegionDepth` value (Phase-1 C-6/C-8 — core-engine *consumes* persistence's `IPersistable`/`FChunkKey`, doesn't publish them):** core-engine serializes the regeneration anchors (`worldSeed` + observer `FUniverseCoord`/`FFrameId` + `SimTime`/`TickIndex` + floating-origin `UniverseOrigin`/`Frame` — CE-10); and pins the `RegionDepth` granule **Forge 9 / Cinder 8** (≈1841/1227 m regions, factory-sim's confirmed ~1 km chunk — CE-9; locked per PHASE1-PLAN §10, 2026-06-14, was 11/9 under a 256 m placeholder), `FChunkKey` being a coarse prefix of world-gen's `FQuadKey`. **No core contract change** — both are values/impls over already-pinned §5 types.

**5a. The browser world lifecycle (NEW 2026-08-03, additive; nothing in §5 above changed).**
- **`Lifetime`** (`web/src/app/Lifetime.ts`) — a scope with an end. `add(label, fn)` / `own(label, obj)` / `addUnsubscribe(label, off)` / `end(): TeardownReport`. `end()` never throws; each step gets its own try/catch and failures come back in the report, so **the caller asserts the failure list is empty**. `add` after `end` THROWS (registering into a dead scope is a leak with no symptom). `DisposeGate` is the idempotence + loudness pair in three lines.
- **`WorldSession`** (`web/src/world/WorldSession.ts`) — `body` / `terrain` / `scatter` / `lifetime` / `epoch` / `isRebooting` / `reboot(bodyId?)` / `audit()`. The composition root supplies a `BuildBodyScope` thunk; this class must never learn the wiring or it becomes a second `Boot.ts`.
- **`Events.census()`** (additive on the existing bus) — per-key subscriber AND emit counts. `Events.on` has always returned an unsubscribe; the defect was four call sites discarding it.
- **`HandleLedger`** (`web/src/sim/wasm/HandleLedger.ts`) — installed inside `loadOfCore`, which is the only module-construction site on the main thread and in every worker, so the census is total by construction rather than opt-in. It **refuses to load** if any `*_destroy` export has a kind whose creator it cannot see, which is the reachable refusing case for the instrument itself.
- **Debug surface:** `of.life()` and `of.reboot(bodyId?)` (`web/src/app/DebugLifecycle.ts`), plus `staleHolders()`. **`reboot` is debug-only on purpose** and must not be wired to a door a player can walk through until the residue in §7 R7 is zero.
- **Worker protocol (additive):** `TerrainInitedMsg.handles` carries the worker's own handle census, which is the only evidence the main thread can get that a rebuilt scope got a NEW heap.

**Contract stability:** these four (+ two events) are the most depended-upon interfaces in the project. Spike 1 made them concrete additively (no breaks); Phase-1 C-7 added `ISimClock::QuiesceAtTickBoundary` (additive). Future breaking changes escalate to Admin (AGENT_ARCHITECTURE §6).

## 5b. Browser (WASM) surface — the pivot's new outbound contract
The nine `/core` domains now also ship to JS through **one flat C ABI**:
[`web/wasm/of_core_api.cpp`](../../web/wasm/of_core_api.cpp), documented signature
by signature in **[docs/web/WASM-BRIDGE.md §4](../web/WASM-BRIDGE.md#4-the-exported-c-api)**.
Two conventions bind every consumer and are as load-bearing as the §5 contracts:
- **Handles, not pointers.** JS holds an `int`; every `*_create` needs its `*_destroy`. Handle id spaces are **per module instance** (each instance has its own heap — see the op-log ownership model in [§5.2](../web/WASM-BRIDGE.md#52-the-ownership-corollary--plan-for-it)).
- **Never cache a heap view or a scratch pointer across a call into WASM.** `-sALLOW_MEMORY_GROWTH` detaches every existing `ArrayBuffer`; re-read `M.HEAPxx` **and** the scratch pointer every time. This is the single most likely integration bug and is spelled out in [§3.2](../web/WASM-BRIDGE.md#32-the-scratch-arena-and-the-allow_memory_growth-footgun).
- **One surface authority, at the ABI boundary too (CE-13).** Every export that answers "where is the ground" reads [`surface_field.h`](../../core/include/of/surface_field.h); RAW is exposed only where RAW is in the name and the doc says diagnostic. Where a flag picks an authority, **`0` picks the oracle**. The per-export table is [WASM-BRIDGE §4.0](../web/WASM-BRIDGE.md#40-surface-authority-which-export-reads-what) and it is enforced by parity CASE 7b/7c, not by good intentions.
The renderer's two hard requirements are met: the surface oracle is a set of plain
scalar-in/double-out exports callable **synchronously on the main thread**
(1.4–3.8 µs), and a chunk crosses as **one pre-interleaved 28 B/vertex buffer**
(`of_chunk_packed`, 1217 verts, 34,076 B) built in 3.39 ms against a 12 ms gate.
**ABI is now 2** (2026-07-25, CE-13): `of_observer_latlon_alt(body, edits, lat,
lon, altM)`, `of_quadmesh_generate(..., rawBase)`, and `of_chunk_max_offset` as a
true bounding radius. `OfCore.ts` checks the version and throws on mismatch, so
the client fails loudly rather than drifting. Note also that the renderer
**de-interleaves** the packed buffer into five sections in the worker: three.js
cannot bind mixed attribute types from one `InterleavedBuffer`, so the "bind it
directly" snippet that used to be in §4.8 was wrong and has been corrected.

## 7. Open questions & risks
- **R7 (NEW, CE-20, 2026-08-03, ROUTED — Admin to allocate): seven collaborators still hold the previous body after a switch, and they are MEASURED, not guessed.** `of.life().stale` compares what each holder currently answers against the live body, which a grep cannot do (it cannot tell a copy that is re-read per frame from one that is frozen). Measured on a Forge→Cinder switch, exactly seven rows are stale and three are clean. **Stale:** `proxy.bodyName` = `ForgeProxy` (the far-scene planet geometry is baked from radius and relief at construction → **rendering**); `sky.uPlanetR` = 600000 against a live 200000 (baked into a `ShaderMaterial` → **rendering**, and RN-840 has just made the sky body-aware at BOOT, which is the same seam one step earlier); `voxelMesh.bodyHandle`, `gameplay.bodyHandle`, `gameplay.bodyRadiusM`, `flight.bodyHandle`, `flight.bodyRadiusM` (**gameplay / physics**). **Clean, and they are the positive controls that stop the census reporting everything as broken:** `oracle.body.radiusM` and `oracle.water.body.radiusM` (re-seated) and `scatter.bodyRadiusM` (rebuilt). The census cannot see anything `Services` cannot reach; what it misses is named here rather than pretended away.
- **R8 (NEW, CE-19, 2026-08-03, the finding worth more than the pass): a GPU instance pool was being freed by an accident of frame timing, and the negative control REFUSED TO GO RED TWICE.** First refusal: `propsPlaced` is the scatter's own counter, so a rebuilt scatter counts back up to the same 10,170 while the old scope's slots sit orphaned in batches that outlive it. **An instrument that cannot see the failure mode it was chosen for.** Second refusal, with the right instrument (`PropLibrary.instances`, decremented by `release`): it still passed, because the loop ticks **nine animation frames** during a rebuild, `TerrainStream.dispose` has already cleared the resident set, and the outgoing scatter's ordinary per-frame reclaim releases all 10,170 slots as a SIDE EFFECT of the world being gone. So the explicit teardown step was deletable with no measurable consequence. Fixed by gating all three `Systems` hooks on `session.isRebooting`, after which the control reads **10,170 → 20,340**. **The general risk this leaves open: an incidental cleanup path makes an explicit one untestable, and there is no way to find the next one except by trying to delete each teardown step and watching what happens.**
- **R9 (NEW, 2026-08-03, other lanes' to triage): four of the five keys on the event bus have never had a subscriber, and two of them are emitted per chunk.** Measured on one boot: `ChunkReady` 309 emits, `StreamUpdate` 20, `ChunkEvicted` 0, `RegimeChanged` 0, all into an empty `Set`. Cost is trivial today and the point is not cost: an event with no subscriber is an interface nobody is honouring, and `ChunkReady`/`ChunkEvicted` are exactly the hooks a future scatter, audio or physics consumer would reach for, so they will be *presumed working* by whoever wires the first one. Either give them a subscriber or delete them.
- **R10 (NEW, 2026-08-03, build-tooling): `npm run check` is red for everybody and has been for some time.** `check:limits` reports **29 files over the 400-line cap** at HEAD, including `Boot.ts` at 527 and `Scatter.ts` at 683. This lane did not create the condition and did not fix it, but a gate that everyone has learned to ignore is INSTRUMENTS.md's central failure and it is currently the state of the project's own aggregate check. `typecheck`, `check:proxies` and `check:boot` are all green.
- **R11 (NEW, 2026-08-03, observed, not attributable to this lane): `probes/discovery.js` is red on its limb-projection claim** ("the out/back fill flip is the LIMB entering the frame ... on-body 3600 -> 3600"). Verified pre-existing by a discriminating run: red **identically** with and without CE-22's one-line change, which is in any case a numeric no-op on Forge (`kind === 'moon' ? 1 : 0` and `bodyId` are both literally 0). Belongs to whoever owns the map's limb test.
- **R6 (NEW, process finding, 2026-07-25):** **A standing rule with no executable guard does not hold.** WG-21 made `surface_field.h` the single surface authority and [DECISIONS.md](../web/DECISIONS.md) standing rule 1 wrote it down; the very next component built against that rule (the WASM bridge) violated it in three places, one of which put the player 2.4 km underground and shipped through a green test suite because nothing asserted the rule. Fixed for this contract by CE-13's CASE 7b/7c. **The generalisation, and the open item: every authority-style invariant in the project needs a test that fails the build, and the test must assert the negative half too** (that the wrong source is still measurably different), or it will one day pass vacuously. Candidates to audit next on the same criterion: the UE surface layer (R2b), deposit/foliage snapping, and anything that will consume `surfaceHeight` across the /core-to-JS boundary.
- **R5 (NEW, characterised and accepted — CE-11):** WASM↔native world-gen is **not** bit-identical (~1.7% of terrain vertices), because the four `libm` transcendentals in the determinism path (`tan` in `warp`, `asin`/`atan2` in `dirToLatLon`, `cos` in `temperatureAt`) are not bit-specified by IEEE-754. **Not a risk while the game is browser-only** (one binary). **Becomes a blocker the moment a native peer is proposed** — a native dedicated server, or a native tool that pre-bakes world content, would generate a different planet from the same seed. Mitigation is known and bounded (vendor those four functions into `/core`); cost is one re-baseline of the seed→world mapping. Escalate to Admin *before* any native-peer work is scheduled, not after. Measured by `node web/wasm/test/diag.mjs`.
- **R1 (critical) — test designed, not yet run:** Does UE5's LWC + Chaos behave well under aggressive floating-origin rebasing at speed? Spike 1 §7 defines explicit **pass/fail criteria** (V2 no-hitch, V3 no-wobble at 10⁹ m, V4 no-kraken at 3 km/s, V5 seamless SOI). **Likely outcome flagged:** *partial pass* — coords/render fine, **Chaos may need replacing for the active vessel** (a physics-domain/Spike-2 escalation). Full fail → revisit D-001 (Unity/DOTS or custom). Still OPEN until the build runs.
- **R2:** double vs int64 fixed-point for the authoritative coord (determinism vs ergonomics). Lean double for v1 (Spike 1 `UniverseCoord` uses double; int64 path deferred); revisit if networking needs determinism.
- **R3 — design settled, validation pending:** Active/OnRails promotion hysteresis. Spike 1 §3.2 pins it: activate 2 km / deactivate 3 km gap + 2 s demote-dwell; promotion immediate, demotion lazy. **RC-10/CE-7 extends the `gap` to be extent-aware (§3.2.1) so coarse chunk proxies and point vessel proxies hysteresis-uniformly — same 2/3 km band + 2 s dwell on the same metric, so no added thrash risk.** Validated by gate V7 (recommend adding a coarse-proxy case: jitter a *chunk* proxy at its extent-inflated boundary, assert no mode oscillation).
- **R4 (Phase-1, DEPENDENCY — RECONCILED, locked per PHASE1-PLAN §10, 2026-06-14):** CE-9's `RegionDepth` (Forge 9 / Cinder 8) uses factory-sim's **confirmed ~1 km factory-chunk extent** (was a ~256 m placeholder → 11/9). Per the formula `RegionDepth(body)=floor(log2(R·(π/2)/E))` with E ≈ 1 km, Admin reconciled the values in the §10 register (no core contract change — only the integer moved). CE-9 is now "Accepted (locked)."

# Web pivot: Admin decision log

Decisions owned by the Admin Master Controller for the Three.js pivot. Agents: read this
before starting web work. Companion docs: [ARCHITECTURE.md](ARCHITECTURE.md) (rendering
and engine), [WASM-BRIDGE.md](WASM-BRIDGE.md) (the `/core` C API), [ASSET-SPECS.md](ASSET-SPECS.md)
(models and the Blender pipeline). Plan of record for the project overall remains
[RETHINK.md](../review-2026-06-16/RETHINK.md), with Phase R consolidation absorbed into this pivot.

| DW-24 | **A structure RESTS on the terrain. It never deforms it.** Placing a foundation, floor, wall or door writes nothing to the voxel layer. | DW-26 (R7) | **The oracle publishes BOTH shapes of "solid" as named, parameterised answers, and a ctest asserts the BOUND between them.** `solidCell` is the voxel shell, quantised to the 1 m lattice, which is what the mesher draws. `solidBelowSurface` is that shell intersected with the smooth surface, which is what a body occupies. Neither is "the" answer and neither is wrong. A core test asserts the two may disagree by at most half a cell diagonal, so the size of the disagreement is a checked property rather than a discovery. `solidForWalker` in `VoxelCollision.ts` is correct and is PROMOTED into the oracle rather than left in the client, because a per-consumer reconciliation left in a consumer is by definition the sixth definition of the surface | This is the fifth multi-hour bug from one ambiguity (UE observer, WASM bridge observer, LOD distance metric, gravity authority, and now the walker colliding with rock 0.87 m above the ground it stands on, which cost 56% of walking speed while every flag read healthy). I asked the world-gen controller to choose between changing the quantisation and per-consumer reconciliation. **It refused both and was right to.** Changing the quantisation cannot succeed: the mismatch is not a bad threshold, it is inherent to sampling a smooth field on a binary lattice, so moving the rule moves WHERE the boundary layer disagrees rather than whether it does, and re-baselines every voxel pin for nothing. Per-consumer reconciliation is precisely what produced five surfaces in the first place. The third option names the ambiguity instead of trying to delete it. This is DW-7's lesson repeating: when a decision offers two unattractive options, the answer is usually a third. **The general rule this establishes: when one authority must answer a question in two shapes, publish both shapes and test the bound between them. An unnamed second shape becomes a fifth definition; a named one is an interface** | 2026-07-26 |

| DW-27 | **The ship target is Steam, as a desktop build in an Electron shell. Consoles are explicitly out of scope** (Reid, 2026-07-26: "fuck consoles, i dont care about developing support for consoles"). **This RAISES the ceiling rather than lowering it, and two earlier decisions should be re-read in that light.** DW-4 ruled out `SharedArrayBuffer` because COOP/COEP headers break OAuth and cross-origin subresources on the open web; in a shell we own the headers, so shared memory is available whenever a workload justifies it. DW-10 chose WebGL2 partly because WebGPU sat at 83.6% browser support against WebGL2's 94.7%; bundling a pinned Chromium makes that number 100% by construction, so WebGPU becomes a question of maturity and of the five-shader cap, not of reach. **Neither is a mandate to go and use them.** Both stay as they are until a measurement asks for the change; the point is that the web-deployment constraints that shaped them no longer bind, and no future lane should design around browser compatibility percentages. Precedent for the packaging itself is solid (CrossCode on NW.js, Vampire Survivors and Cookie Clicker on Electron), though all of those are 2D or light 3D, so they prove the shell works and not that our rendering load does. **What remains genuinely unproven is scale**: 41 draw calls at 2.1 ms is a small scene on a strong GPU, and every performance number this project has was measured on a handful of buildings rather than on a base. Electron packaging and a scale test are to be spiked EARLY, while the client is ~120 files, not at the end. The reason a wrong answer here is survivable at all: `/core` is engine-agnostic C++ with 22 green suites and has already survived one engine migration, so the expensive tested part is portable and the part bound to a rendering technology is the cheap part | 2026-07-26 |

## Standing engineering rules for web work

1. **One surface authority.** Everything reads `surface_field.h` through the WASM bridge. No module re-derives terrain height or solidity. This is the rule whose absence caused every major bug in the UE build.
2. **No god objects.** Modules have one responsibility and are named for it. An integration pass follows every few feature passes.
3. **Verification is driven, not posed.** Acceptance means a scripted browser run with real input and captured console plus screenshots, never a static render.
4. **Determinism is a feature.** Same seed and same op sequence produce the same world. Parity against the C++ suites is the gate for any core change.
5. **Never cache a WASM heap view or scratch pointer across a call into WASM.** `ALLOW_MEMORY_GROWTH` detaches every `ArrayBuffer` on growth. Re-read `Module.HEAPxx` and the pointer on every call, and copy out before the next one. See `WASM-BRIDGE.md` §3.2. This is the single most likely source of silent corruption in the renderer.
6. **Positions cross the boundary as float32 relative to a per-chunk 64-bit anchor**, never as absolute planet-scale floats. Measured: 0.9 mm error at walking LOD, against 71.5 mm for absolute f32 at a 600 km radius. Losing the anchor is precisely how the UE build produced floating players and floating nodes.
7. **A defect that one system hides is still a defect, and the hiding system will be removed.** The W2 "279-pixel limb fringe" was 150,265 missing pixels with the `PlanetProxy` turned off: half the planet was back-face culled and the proxy was painting over it. Every visual claim needs the covering layer disabled at least once. `?proxy=0`, `?shell=0`, `?atmos=0`, `?stars=0`, `?shadows=0`, `?fade=0` and `?stitch=0` exist so that any single layer can be isolated, and a measurement that has not isolated its subject is an opinion.
8. **Never discriminate on the sign of a computed float.** GLSL evaluates `-0.0 >= 0.0` as true, which put the outgoing half of the terrain cross-dissolve on the incoming branch for the first frame of every dissolve. Offset the encodings into disjoint ranges instead.

9. **An ABI bump is ATOMIC across the bridge.** The shim's `of_abi_version`, the rebuilt and synced wasm, and the client's `OF_ABI_VERSION` together with any callers whose signatures changed all land in **one commit, and that commit boots**. Incremental commits are right everywhere else; the bridge is the one place where half a change is a broken build rather than an unfinished one. This cost two separate breaks on 2026-07-26 alone: the shim reporting 3 against a client expecting 2, and later a shim at 5 against a client at 4 that left HEAD unbootable and blocked a second agent entirely, since no probe can run against a page that will not load. Twice in one day is a process defect, not bad luck. Note that the guard itself is working correctly in both cases: refusing to run a client against a bridge it does not agree with is precisely what prevents silent heap corruption, so **the fix is never to flip the constant**, it is to make the client actually speak the new ABI. Corollary, learned the same day: never print a hard-coded ABI number in a banner. `main.ts` claimed `abi=2` while the shim returned 3 and then 4, and it bought a wrong diagnosis.

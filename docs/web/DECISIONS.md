# Web pivot: Admin decision log

Decisions owned by the Admin Master Controller for the Three.js pivot. Agents: read this
before starting web work. Companion docs: [ARCHITECTURE.md](ARCHITECTURE.md) (rendering
and engine), [WASM-BRIDGE.md](WASM-BRIDGE.md) (the `/core` C API), [ASSET-SPECS.md](ASSET-SPECS.md)
(models and the Blender pipeline). Plan of record for the project overall remains
[RETHINK.md](../review-2026-06-16/RETHINK.md), with Phase R consolidation absorbed into this pivot.

| DW-1 | `/core` ships to the browser as **WebAssembly (Emscripten)**, not a TypeScript port | Preserves 22 green suites, bit-exact determinism, and the 64-bit position hashing. A port would forfeit all three and cost weeks | 2026-07-05 |

| DW-12 | **No physics engine for the player.** Capsule resolved against the `/core` surface oracle and `solidCell`. | DW-13 | **W0 gate: the terrain chunk boundary must be microbenchmarked before anything is built on it.** Chunks cross as one pre-packed interleaved buffer (about 28 B/vert) written into the WASM heap for zero-copy JS views, and must meet 12 ms per 1,217-vertex chunk | This is risk R1, the single highest technical risk in the pivot. Naive Embind traversal of `std::vector<Vec3>` doubles would be fatal to the frame budget, and discovering that at W5 instead of W0 would invalidate the streaming design | 2026-07-05 |

| DW-14 | **The WASM build is the canonical world generator.** Native `/core` builds are a development and testing convenience, not the reference world | The spike measured a **1 ULP `std::tan` divergence** between mingw-w64 libm and emscripten/musl at 2.83% of lattice arguments. Because height is position-hashed from the direction's raw bits by design, 1 ULP in yields an unrelated height at roughly 1.7% of vertices. Both builds are internally perfect and each is bit-identical to itself (19/19 self-determinism, and all sim logic, voxels, persistence bytes and LOD selection are exact cross-toolchain at 94/94). For a single-binary browser target this is invisible: every player gets the same planet | 2026-07-05 |
| DW-15 | **Hard gate (risk R5 / CE-11): before any native peer exists**, an authoritative multiplayer server or a native port, vendor `tan`, `asin`, `atan2` and `cos` into `/core` and re-baseline the terrain pins. Do not ship a native peer against libm | A native server and a browser client would otherwise grow different planets from the same seed, which is a silent, catastrophic desync. Evaluate the performance cost at that time: `warp()` calls `tan` per vertex per axis on the meshing hot path, so a software implementation is not free | 2026-07-05 |
| DW-16 | **The main thread owns the authoritative `VoxelEdits`;** workers replay an edit op-log or load a `persistence.h` snapshot. Heaps are never shared | One single-threaded WASM instance per JS thread (no SharedArrayBuffer, per DW-4), so each instance has its own heap. Making ownership explicit prevents the class of bug where a dig is visible to the mesher but not the character, which is the web analogue of the five-surfaces failure | 2026-07-05 |
| DW-17 | **Persistence moves to IndexedDB/OPFS on the JS side** (`persistence_file.h` is excluded from the WASM build). The `persistence.h` byte format is unchanged and remains the source of truth | `std::filesystem` does not exist in the browser. The serializer works as-is, so only the container changes. This also finally delivers the unified save that Phase R4 never reached: inventory, buildings, research and voxel edits in one atomic slot | 2026-07-05 |

## Standing engineering rules for web work

1. **One surface authority.** Everything reads `surface_field.h` through the WASM bridge. No module re-derives terrain height or solidity. This is the rule whose absence caused every major bug in the UE build.
2. **No god objects.** Modules have one responsibility and are named for it. An integration pass follows every few feature passes.
3. **Verification is driven, not posed.** Acceptance means a scripted browser run with real input and captured console plus screenshots, never a static render.
4. **Determinism is a feature.** Same seed and same op sequence produce the same world. Parity against the C++ suites is the gate for any core change.
5. **Never cache a WASM heap view or scratch pointer across a call into WASM.** `ALLOW_MEMORY_GROWTH` detaches every `ArrayBuffer` on growth. Re-read `Module.HEAPxx` and the pointer on every call, and copy out before the next one. See `WASM-BRIDGE.md` §3.2. This is the single most likely source of silent corruption in the renderer.
6. **Positions cross the boundary as float32 relative to a per-chunk 64-bit anchor**, never as absolute planet-scale floats. Measured: 0.9 mm error at walking LOD, against 71.5 mm for absolute f32 at a 600 km radius. Losing the anchor is precisely how the UE build produced floating players and floating nodes.

# Web pivot: Admin decision log

Decisions owned by the Admin Master Controller for the Three.js pivot. Agents: read this
before starting web work. Companion docs: [ARCHITECTURE.md](ARCHITECTURE.md) (rendering
and engine), [WASM-BRIDGE.md](WASM-BRIDGE.md) (the `/core` C API), [ASSET-SPECS.md](ASSET-SPECS.md)
(models and the Blender pipeline). Plan of record for the project overall remains
[RETHINK.md](../review-2026-06-16/RETHINK.md), with Phase R consolidation absorbed into this pivot.

|---|---|---|---|
| DW-1 | `/core` ships to the browser as **WebAssembly (Emscripten)**, not a TypeScript port | Preserves 22 green suites, bit-exact determinism, and the 64-bit position hashing. A port would forfeit all three and cost weeks | 2026-07-05 |
| DW-2 | **Vanilla three.js + TypeScript + Vite**; game UI is an **HTML/CSS overlay** | React reconciliation is a liability in a streaming game loop. HTML UI is a large win over UMG for inventory, crafting and HUD | 2026-07-05 |
| DW-3 | **Multi-pass scaled space** (sky · far scaled · near 1:1 · FP view model), depth cleared between. **AMENDED 2026-07-05:** the camera split is primary, **reversed-Z** (`EXT_clip_control`, 86% support) is the depth mechanism, logarithmic depth is fallback only | RN-1 from the original design, and what makes the surface to orbit seam tractable. Amended on the architecture agent's evidence: three's own docs call reversed-Z faster and more accurate than log depth, which needs `gl_FragDepth`, disables Early-Z, breaks MSAA, and infects every custom shader. Giving the FP view model its own pass also lets the near plane move from 0.01 m to 0.1 m, buying a decade of precision and killing view-model clipping structurally | 2026-07-05 |
| DW-4 | **Web Workers** own terrain and voxel meshing and the factory tick, with an independent WASM instance per worker. **AMENDED 2026-07-05: transferables only. Amended on evidence: the standard cross-origin-isolation Vite plugin has been unmaintained since 2022, COOP/COEP breaks cross-origin subresources and OAuth, Emscripten documents pthreads plus `ALLOW_MEMORY_GROWTH` as slow, and no workload needs it (RC-8 measured the factory stream at single-digit MB/s) | 2026-07-05 |

| DW-6 | The UE layer is **frozen, not deleted**: tag `ue-frozen-2026-07-05`, unfinished R2b work on `archive/ue-r2b-wip` | It is the reference implementation for gameplay wiring. Keep it readable, stop investing in it | 2026-07-05 |
| DW-7 | **Player rig**: headless automatic weights first; escalate to a hand-authored `.blend` only if deformation is visibly bad. **RESOLVED 2026-07-05 by a third option: scripted weights.** Blender's bone-heat solver failed silently (returned without error, left 144 of 698 vertices unweighted, since bone heat needs a closed manifold and this character is intersecting tubes and boxes). Render the mesh wherever a connection exists, as Factorio-style feedback | Keeps the build menu honest (players place miners, belts, smelters, assemblers) while making connections legible. Revisit if manual routing becomes a design goal | 2026-07-05 |

| DW-12 | **No physics engine for the player.** Capsule resolved against the `/core` surface oracle and `solidCell`. Rapier is considered only at W8, only for vessels | O(1), deterministic, and structurally incapable of disagreeing with the rendered surface. The UE build's cooked-collision path is exactly where the float and seam bugs lived | 2026-07-05 |
| DW-13 | **W0 gate: the terrain chunk boundary must be microbenchmarked before anything is built on it.** Chunks cross as one pre-packed interleaved buffer (about 28 B/vert) written into the WASM heap for zero-copy JS views, and must meet 12 ms per 1,217-vertex chunk | This is risk R1, the single highest technical risk in the pivot. Naive Embind traversal of `std::vector<Vec3>` doubles would be fatal to the frame budget, and discovering that at W5 instead of W0 would invalidate the streaming design | 2026-07-05 |

| DW-14 | **The WASM build is the canonical world generator.** Native `/core` builds are a development and testing convenience, not the reference world | The spike measured a **1 ULP `std::tan` divergence** between mingw-w64 libm and emscripten/musl at 2.83% of lattice arguments. Because height is position-hashed from the direction's raw bits by design, 1 ULP in yields an unrelated height at roughly 1.7% of vertices. Both builds are internally perfect and each is bit-identical to itself (19/19 self-determinism, and all sim logic, voxels, persistence bytes and LOD selection are exact cross-toolchain at 94/94). For a single-binary browser target this is invisible: every player gets the same planet | 2026-07-05 |
| DW-15 | **Hard gate (risk R5 / CE-11): before any native peer exists**, an authoritative multiplayer server or a native port, vendor `tan`, `asin`, `atan2` and `cos` into `/core` and re-baseline the terrain pins. Do not ship a native peer against libm | A native server and a browser client would otherwise grow different planets from the same seed, which is a silent, catastrophic desync. Evaluate the performance cost at that time: `warp()` calls `tan` per vertex per axis on the meshing hot path, so a software implementation is not free | 2026-07-05 |
| DW-16 | **The main thread owns the authoritative `VoxelEdits`;** workers replay an edit op-log or load a `persistence.h` snapshot. Heaps are never shared | One single-threaded WASM instance per JS thread (no SharedArrayBuffer, per DW-4), so each instance has its own heap. Making ownership explicit prevents the class of bug where a dig is visible to the mesher but not the character, which is the web analogue of the five-surfaces failure | 2026-07-05 |
| DW-3 (closed) | **Reversed-Z confirmed as the default by measurement at W2**, with a recorded ceiling and log depth kept as a measured fallback | The `?scenario=zfight` probe sweeps five scales (1 m to 400,000 km) as green/red coplanar pairs and reads back the pixels. The default framebuffer's depth is **24-bit fixed point**, so reversed-Z cannot deliver its float-buffer headline win, but it still beats plain depth by roughly 50x (2 km at 2 m separation: 2.1% vs 100% bleed). It resolves 1e-4 of the distance within 2 km and 1e-1 at 60 km; log depth resolves 1e-5 everywhere. Nothing is at risk because `nearDepthCutoff` moves terrain beyond about 15 km into the far scene. Full curve in ARCHITECTURE.md section 16.2 | 2026-07-25 |
| DW-17 | **Persistence moves to IndexedDB/OPFS on the JS side** (`persistence_file.h` is excluded from the WASM build). The `persistence.h` byte format is unchanged and remains the source of truth | `std::filesystem` does not exist in the browser. The serializer works as-is, so only the container changes. This also finally delivers the unified save that Phase R4 never reached: inventory, buildings, research and voxel edits in one atomic slot | 2026-07-05 |

| DW-18 | **Forge gets Kerbin-like body parameters: 600 km radius with roughly 9.81 m/s^2 surface gravity** (an artificially dense world), rather than the 0.587 m/s^2 the current mass implies | W2 measured a 4.8 second jump airtime, which reads as broken rather than as low gravity. KSP solved this exact problem the same way: Kerbin is a 600 km world with Earth surface gravity, which keeps walking honest while leaving orbital velocity around 2.3 km/s, well inside playable delta-v budgets. Gameplay feel wins over deriving mass from radius | 2026-07-05 |
| DW-19 | **Terrain LOD under the player must reach 2 m or finer ground resolution before W5 (digging).** `maxDepth` currently defaults to 12, giving a 7.2 m grid at the feet | 1 m voxel digging into a 7.2 m heightfield grid would visibly disagree with itself, which is the same class of defect as the five surfaces: two representations of one ground. Resolve as a tuning pass with measured chunk-count and frame cost, not by guessing a number | 2026-07-05 |
| DW-20 | **Verification harnesses are themselves suspect until proven.** Any headless probe must demonstrate it advanced the simulation (tick counts, distance travelled) before its measurements are trusted | W2 found headless Chrome does not pump `requestAnimationFrame` continuously, so a 20 second scripted walk advanced only 90 ticks, and that `--evalfile` probes silently returned `undefined` through automatic semicolon insertion. Both silently invalidated every measurement taken before them. A green probe that never ran is worse than no probe | 2026-07-05 |

## Standing engineering rules for web work

1. **One surface authority.** Everything reads `surface_field.h` through the WASM bridge. No module re-derives terrain height or solidity. This is the rule whose absence caused every major bug in the UE build.
2. **No god objects.** Modules have one responsibility and are named for it. An integration pass follows every few feature passes.
3. **Verification is driven, not posed.** Acceptance means a scripted browser run with real input and captured console plus screenshots, never a static render.
4. **Determinism is a feature.** Same seed and same op sequence produce the same world. Parity against the C++ suites is the gate for any core change.
5. **Never cache a WASM heap view or scratch pointer across a call into WASM.** `ALLOW_MEMORY_GROWTH` detaches every `ArrayBuffer` on growth. Re-read `Module.HEAPxx` and the pointer on every call, and copy out before the next one. See `WASM-BRIDGE.md` §3.2. This is the single most likely source of silent corruption in the renderer.
6. **Positions cross the boundary as float32 relative to a per-chunk 64-bit anchor**, never as absolute planet-scale floats. Measured: 0.9 mm error at walking LOD, against 71.5 mm for absolute f32 at a 600 km radius. Losing the anchor is precisely how the UE build produced floating players and floating nodes.
